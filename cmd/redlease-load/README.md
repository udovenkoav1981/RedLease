# Нагрузочный тест на отдельно запущенных серверах

`redlease-load` — отдельный клиентский генератор нагрузки. Он **не запускает и
не останавливает lock-server**: серверы нужно поднять вручную до старта теста и
передать их адреса через `-targets` либо получить из etcd. Соединения —
plaintext TCP, поэтому используйте инструмент только в доверенной тестовой
сети.

Например, запустите сервер в другом терминале:

```sh
go run ./cmd/redlease-server -listen=127.0.0.1:17379
```

Дождитесь выхода сервера из restart quarantine. Затем запустите матрицу для
`client1of1` и общего `client` в топологии 1/1:

```sh
go run ./cmd/redlease-load -targets=127.0.0.1:17379 > load-1of1.csv
```

Для топологии 3/5 запустите **пять независимых** серверов на разных адресах;
укажите их все в одном порядке:

```sh
go run ./cmd/redlease-load -client=client -quorum=3/5 \
  -targets=127.0.0.1:17379,127.0.0.1:17380,127.0.0.1:17381,127.0.0.1:17382,127.0.0.1:17383 \
  > load-3of5.csv
```

В режиме etcd укажите тот же endpoint и prefix, с которыми запущены серверы:

```sh
go run ./cmd/redlease-load -client=client -quorum=3/5 \
  -etcd-endpoint=http://127.0.0.1:2379 -etcd-prefix=redlease \
  > load-3of5.csv
```

Для схем 1/1, 2/3 и 3/5 генератор использует соответственно первые 1, 3 или 5
ключей `PREFIX-redlease-server-N`. Он ожидает появления всех необходимых
ключей, сохраняет их порядок и следит за изменениями через etcd watch. При
изменении, удалении или повторном создании ключа клиенты пересоздаются с новым
набором адресов. Пока полный набор недоступен, новые Acquire завершаются
ошибкой и повторяются с обычным backoff; уже выданные lease сохраняют ссылку на
предыдущее поколение клиента, чтобы их Release успел уйти. `-targets` и
`-etcd-endpoint` взаимоисключающие.

Для короткой проверки можно уменьшить матрицу:

```sh
go run ./cmd/redlease-load -targets=127.0.0.1:17379 \
  -clients=2,4 -leases-per-client=16,32 -duration=2s
```

Чтобы во время прогона собирать клиентскую latency через Prometheus, включите
отдельный HTTP endpoint:

```sh
go run ./cmd/redlease-load -targets=127.0.0.1:17379 \
  -clients=1 -leases-per-client=2048 -duration=10s \
  -metrics-listen=127.0.0.1:17390
```

Метрики доступны по `http://127.0.0.1:17390/metrics`. Если
`-metrics-listen` не задан, endpoint не запускается. Histogram
`redlease_client_acquire_duration_seconds` агрегирует все клиенты текущей
точки матрицы и разделяет результаты label `result="acquired"` и
`result="not_acquired"`. При переходе к следующей точке создаётся новый набор
клиентов, поэтому histogram начинается заново; Prometheus рассматривает это
как counter reset. При etcd-reconfigure статистика поколений суммируется до
конца текущей точки. Endpoint также экспортирует стандартные `go_*` и
`process_*` metrics.

Матрица по умолчанию: 2/4/8/16/32 клиента × 16/32/64/128/256 одновременных
lease на клиента, обе реализации в топологии 1/1. Каждый worker циклически
захватывает новый уникальный key, держит lease в течение `-hold` (10 мс) и
вызывает Release. После неудачного Acquire генератор повторяет попытку с
randomized exponential backoff. `-ttl-ms` (1000 мс) задаёт запрошенный TTL,
`-response-timeout-ms` (1000 мс) — timeout ответа сервера. У серверов должны
быть подходящие `MaxTTL` и `MaxKeys`; их конфигурацию инструмент не меняет.

Для каждой точки выбирается случайное начальное значение, после чего каждый
worker использует собственную непересекающуюся последовательность `uint64`-ключей
без общей синхронизации. После замера
клиенты остаются подключёнными ещё `-settle` (по умолчанию TTL + response timeout
+ 100 мс), чтобы асинхронные Release успели уйти до следующей точки. Эта пауза
не входит в измеряемое время. Старые ключи могут оставаться в памяти сервера до
его очистки; при достижении `MaxKeys` результаты будут отражать также лимит
ёмкости, а не только конкуренцию клиентов.

CSV содержит строку на каждую точку: успешные и неуспешные Acquire, ошибки
`KEY_LIMIT_REACHED`, lease, успевшие стать невалидными до Release, частоту
успешных Acquire, минимум и максимум частоты среди клиентов, отношение
min/max, среднюю задержку Acquire и приблизительные p50/p95/p99. CSV пишется в
stdout, ошибки — в stderr. Сравнивайте строки при одинаковых quorum, TTL,
времени удержания и конфигурации серверов. Renew не измеряется.
